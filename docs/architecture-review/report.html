Candidate 1 Strong local-substitutable

Deepen the managed ~/.bashrc block

  • {dircomp-root}/install.sh:26-58, 102-108
  • {dircomp-root}/uninstall.sh:6-31
  • {dircomp-root}/test/installer.sh

ProblemMarker constants, whole-line counting, the begin-before-end check and the awk rewrite exist twice. Commits 657a816 and 4a8725f each had to edit both copies. uninstall.sh has no test: no reference to it in test/.

SolutionOne module owns the block's lifecycle: inspect state, write, remove. Install and uninstall become callers of it.

Benefits
  • locality: marker bugs fixed once, not twice
  • leverage: both entry points share one interface
  • tests cross one interface; uninstall becomes testable
  • the destructive path (rewriting ~/.bashrc) stops being untested

Constraint, not an ADR: install.sh runs as curl | bash and cannot source a sibling file. Where the shared module lives is the first thing to settle.

Candidate 2 Worth exploring in-process

Hide the spec model's key grammar

  • {dircomp-root}/lib/dircomp.bash:101-195 (parse, has, takes_value)
  • {dircomp-root}/lib/dircomp.bash:228-258 (offer)
  • {dircomp-root}/lib/dircomp.bash:311-331 (classify)

ProblemThe key grammar (n, f, s + path) is hand-built on 7 lines in 3 functions. The model travels as four variables that _dircomp declares local (:261-262) and _dircomp_parse fills by dynamic scope; _dircomp_offer also reads the caller's $typed (5 uses, :250-255). The interface is a naming convention.

SolutionA Spec module answers queries about nodes, flags and slots. Key strings and the four variables become its implementation.

Benefits
  • locality: grammar changes touch one module
  • interface shrinks; implementation absorbs key building
  • the walk reads like SPEC.md, not like string surgery
  • hidden coupling through $typed disappears

Risk: bash has no records. A query interface that forks a subshell per lookup adds latency to every TAB; the interface has to return through variables.

Candidate 3 Worth exploring ports & adapters

Give the walk and classify rules their own seam

  • {dircomp-root}/lib/dircomp.bash:260-348 (_dircomp, 89 lines)
  • {dircomp-root}/lib/dircomp.bash:28-62 (host detection)
  • {dircomp-root}/test/tab.py

ProblemWalk, classify, emit and word-break trimming share one 89-line function, reachable only through bash-completion and a real TAB. Sourcing the library without bash-completion exits 1. The suite ran 125 cases in 2m12s on 24 October 2026; a failing case does not say which rule failed.

SolutionPut the rules behind their own interface (SPEC.md, “Reading the line”). The host adapter keeps loader detection, the fallback stub and word-break handling.

Benefits
  • locality: the SPEC.md walk rules live in one module
  • tests cross the seam without a pty
  • pty suite narrows to the host adapter
  • two bash-completion generations: the adapter seam is already real

Do not replace the pty harness (184d65a). It is the only test that exercises the integration, where 76f71c1 fixed bugs. This adds a second test surface. It pays only if the walk rules keep moving: 707fbd3 touched 293 lines of the library.

Considered, no card

  • Release identity in 5 lines across 3 files (README.md:23, 43; install.sh:4, 21; lib/dircomp.bash:25). The tag pin is deliberate for curl | bash; a release step fixes it, a module does not.
  • Host detection (lib/dircomp.bash:37-62) already carries two real adapters (bash-completion 2.11 and 2.12 names). Leave it.
  • _dircomp_resolve and _dircomp_find pass the deletion test: deleting them spreads symlink and walk-up logic across callers.
